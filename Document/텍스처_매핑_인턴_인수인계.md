# 그림 → 캐릭터 텍스처 매핑 — 인수인계 (초안 2026-09-11)

> 이 문서는 영암 LiveSketch 프로젝트의 캐릭터 텍스쳐 매핑 작업을 인수인계 하기 위한 문서입니다.                                                                                

## 1. 무엇을 만드는가

관람객이 카드에 색칠한 그림을 스캔하면, 그 그림이 전시 화면 속 3D 캐릭터의 옷·몸 텍스처로 입혀진다. 이 저장소의 목표는 그 **"그림 한 장 → 캐릭터에 입힐 텍스처 한 장"** 변환을 만드는 것이다. 스캔, 파일 수신, 캐릭터 등장은 전시 프로젝트 쪽에 이미 있으므로 여기서는 다루지 않는다.

- 전시 캐릭터는 360도 돌아간다. **앞면과 뒷면 그림이 모두 제공되며, 각 그림을 캐릭터의 해당 면에 매핑하고 옆구리를 자연스럽게 섞는** 방식으로 구현한다.
- 관람객이 색칠하는 템플릿은 UV 전개도가 아니라 **캐릭터의 앞모습과 뒷모습을 그린 색칠용 도안**이어야 한다. 이 과제의 핵심은 도안에 색칠한 내용이 3D 캐릭터의 해당 부위에 나타나도록, 도안의 각 영역을 모델의 UV에 맞게 배치하는 것이다.

## 2. 범위 / 범위 밖

**범위**

- 카드 PNG에서 그림 영역을 잘라내는 것(카드 테두리·여백·속성 표시 제거)
- 잘라낸 앞면·뒷면 그림을 각각 모델의 해당 UV 영역에 맞게 옮기는 것(조회표든 1:1 UV든 방식은 조사로 결정)
- 앞면·뒷면 그림의 옆구리 경계를 자연스럽게 섞고, 그림에 없는 부분(옆면·안쪽 등)을 어색하지 않게 채우는 것
- 위 과정을 UE 안에서 함수 하나로 실행해 텍스처를 만드는 것 + 결과를 보여주는 데모 레벨

**범위 밖**

- 스캔 앱, 공유폴더, OSC 수신, 캐릭터 스폰·이동·전시 흐름
- 캐릭터 모델링·리깅·애니메이션(리소스팀)
- 원근 보정(스캔 앱이 이미 보정한 `warped_*.png`를 준다)

## 3. 입출력 계약 (통합을 위해 반드시 지킬 것)

```
입력  : 보정된 카드 이미지 1장 (PNG, 예: warped_006_20260820141536.png)
출력  : 지정 캐릭터 메시에 그대로 입힐 수 있는 텍스처 1장 (UTexture2D 또는 RenderTarget, 크기 [ ])
형태  : UE 함수 하나  (예) UTexture* BuildCharacterTexture(UTexture2D* CardImage, int32 TemplateId)
        BP에서도 호출 가능해야 함 (BlueprintCallable)
```

- 템플릿마다 모델(또는 UV)이 다를 수 있으므로 템플릿 번호 → 조회표/설정 자료를 데이터 에셋으로 묶는다.
- 전시 프로젝트는 지금 재질 파라미터 `TextureParameterName`에 텍스처를 꽂는 방식이라, 출력이 텍스처 한 장이면 통합은 한 줄이다.
- 코드는 플러그인 하나 또는 폴더 하나(`Source/CardTexture/` 같은)로 묶어 다른 프로젝트에 복사만 하면 붙도록 한다.

## 5. 완료 기준

1. 정면과 후면에서 봤을 때 각각의 앞면·뒷면 그림이 늘어나거나 찌그러지지 않고 그대로 보인다.
2. 옆·뒤로 돌려도 비어 있거나 검은 부분이 없다.
3. 앞/뒤 이음새(옆구리)가 한눈에 띄지 않는다.
4. 템플릿의 선(윤곽선)은 `[ 남긴다 / 지운다 ]` 로 처리한다.
5. 카드 여백·속성 표시·테두리는 텍스처에 들어오지 않는다.
6. 카드 1장 처리에 `1초`를 넘기지 않는다(전시 중 실시간 호출).

## 8. 저장소 운영 규칙 (GitHub)

- 비공개 저장소, 인턴 2명 협력자. **첫 커밋 전에 LFS 설정**: `.gitattributes`에 `*.uasset *.umap *.png *.fbx *.psd` 등을 LFS로. UE용 `.gitignore`(Binaries, Intermediate, Saved, DerivedDataCache, .vs) 적용.
- **모든 일은 이슈로 시작**: 작업 이슈(무엇을, 왜, 완료 조건)와 질문 이슈(해본 것, 막힌 곳, 스크린샷)를 템플릿으로 둔다. 라벨: `작업`, `질문`, `버그`, `결정필요`.
- **코드는 PR로**: `main` 직접 푸시 금지. 브랜치 `feature/<이슈번호>-<짧은설명>`. PR 본문에 "무엇을 바꿨고 어떻게 확인했는지" 두 줄 이상. 서로 리뷰 후 담당자가 병합.
- **문서는 저장소 안에**: `README.md`(실행법), `Document/DECISIONS.md`(결정과 이유, 날짜 순), `Document/RESEARCH.md`(조사 결과), `Document/INTEGRATION.md`(전시 프로젝트에 붙이는 법)
- 커밋 메시지는 한국어 한 줄 + 필요하면 본문. 예: `조회표 방식 2D 실험: 카드 5장 자르기 결과 추가`.
- 큰 바이너리(모델·PSD)는 꼭 필요한 것만. 실험용 캡처는 `Document/images/`에 작게.
